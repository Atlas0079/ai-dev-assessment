# 接手模拟订单服务
使用Java8、Spring Boot 2.1.13、Maven两个模块、MongoTemplate。起始项目已有登录、服务列表、创建、列表、详情。
完成接单、取消、完成，并修复详情越权。沿用已有接口与分层，保持原有功能。
customer1/customer2为客户，provider1/provider2为陪玩。只模拟已支付订单，不实现真实支付。
PENDING可由陪玩accept变ACCEPTED，或由本人客户cancel变CANCELLED；ACCEPTED仅接单人complete变COMPLETED。其他转换拒绝。
客户只看本人订单；陪玩可看PENDING摘要和本人已接订单。详情有故意留出的归属缺陷，需修复。
接单、取消、完成三个状态写动作带Idempotency-Key；同身份/订单/动作/key相同note重放返回首次成功结果，不同note返回409。
成功增加一次version；并发抢单或接单与取消只允许一次成功修改。不要把Redis锁视为数据库原子更新的替代。
数据库状态、幂等结果需一致，断连后可重试核验。评测可能注入一次数据库写连接中断，不要求多文档事务。
保留Order.id到Mongo _id的默认映射。不要建立无意义的id空值唯一索引。
部署提供MONGO_URI。单进程服务重启后订单仍存在。正式测试不得使用内存DAO替代MongoDB。

接口细节见《接口与检查边界.md》。本版仅生成可执行检查证据，不生成综合分数。页面和代码质量另行验收。
