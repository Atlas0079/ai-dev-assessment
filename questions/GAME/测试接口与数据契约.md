# GAME接口与数据契约 2.0

本文件是候选人必须实现的约定。JSON使用UTF-8；业务成功返回HTTP200和对象，错误返回对应HTTP错误状态及 {"code":"错误标识"}。允许统一包装成功结果为 {"code":0,"data":对象}。所有玩家请求使用 Authorization: Bearer <playerToken>，不能根据请求体的playerId授权。请求体中的requestId必须是非空字符串。

## 业务接口

| 方法和路径 | 请求 | 200响应 |
|---|---|---|
| GET /healthz | 无 | {"status":"ok"}，可附加运行信息 |
| POST /v1/rooms | {"displayName":"A"} | roomId、playerId、playerToken（均为字符串） |
| POST /v1/rooms/{roomId}/join | {"displayName":"B"} | roomId、playerId、playerToken |
| GET /v1/rooms/{roomId} | 成员令牌 | players（玩家ID数组，座位顺序）、ready（ID→布尔值）、host（ID）、gameId（开局前null） |
| POST /v1/rooms/{roomId}/ready | {"ready":true,"requestId":"ready-1"} | {"ready":{"玩家ID":true}} |
| POST /v1/rooms/{roomId}/start | {"requestId":"start-1"} | 下述公开牌局对象 |
| GET /v1/games/{gameId} | 玩家令牌 | 公开牌局对象 |
| POST /v1/games/{gameId}/actions | 动作对象 | 动作执行后的公开牌局对象 |

动作示例：
```json
{"requestId":"action-1","expectedRevision":0,"type":"PLAY","cardId":"a","chosenColor":"B"}
```
PLAY必填cardId；WILD另需chosenColor=R/Y/B/G。DRAW不需cardId；即使携带cardId也忽略该字段。expectedRevision是非负整数，不接受布尔值。相同玩家、同一对局、相同requestId的成功请求，相同请求体返回首次响应；不同请求体返回409。重放判断在回合、终态、版本检查之前。ready/start按玩家、房间、操作、requestId幂等；ready重放返回首次ready快照。

公开牌局对象只包含以下字段，不额外返回调试状态：
```json
{
  "gameId":"g1","currentPlayerId":"A","direction":1,"currentColor":"R",
  "revision":0,"status":"PLAYING","winnerId":null,
  "hand":[{"cardId":"a","color":"R","value":"1"}],
  "players":[{"playerId":"A","count":1},{"playerId":"B","count":1}],
  "top":{"cardId":"top","color":"R","value":"3"},"drawCount":0
}
```
hand只含请求者自己的牌，players保持座位顺序，只含ID和牌数。DRAW后新牌追加到手牌末尾，PLAY移除对应牌并保持其他手牌顺序。不得返回他人手牌或未知牌库的cardId、牌面、顺序。令牌必须绑定具体房间/对局；不同fixture即使玩家ID相同也不能互相访问。

## 测试接口（必须实现）

服务启动时从环境读取 EVAL_FIXTURES 和 EVAL_CONTROL_TOKEN。测试模式开启且非空控制令牌正确时才允许以下两个接口。关闭测试模式返回404；测试模式开启但令牌缺失、错误或为普通玩家令牌，返回401或403。

1. POST /__test/fixtures：请求格式见 samples/fixture.json；返回 {"gameId":"新ID","tokens":{"A":"玩家令牌A","B":"玩家令牌B"}}。每次新建独立牌局，不能覆盖其他牌局。tokens覆盖所有输入玩家。
2. GET /__test/games/{gameId}：返回与fixture同格式的完整状态，加一个gameId字段。不返回令牌、内部幂等记录等额外字段。不存在时404。

两个接口都用 Authorization: Bearer <EVAL_CONTROL_TOKEN>。读取完整状态不应改变任何状态。fixture必须直接进入正常玩法引擎，不能返回预制测试答案。

## 完整状态字段

| 字段 | 类型与约束 |
|---|---|
| schemaVersion | 固定字符串 "1.0"（本接口的数据版本） |
| players | 2—4人的有序数组；每项为id（非空、局内唯一字符串）、hand（Card数组） |
| drawPile | Card数组，索引0首先抽取 |
| discardPile | 非空Card数组，末尾为当前弃牌顶 |
| currentPlayerId | 必须是players中的ID |
| direction | 整数1（沿座位数组）或-1（逆向） |
| currentColor | R/Y/B/G；非万能顶牌时等于顶牌color |
| revision | 非负整数，布尔值不合法 |
| status | 注入时PLAYING；运行后PLAYING或FINISHED |
| winnerId | 注入时null；结束后为胜者ID |

Card仅含cardId（非空字符串）、color、value。数字value为字符串"0"—"9"；普通功能牌为SKIP/REVERSE/DRAW2，color为R/Y/B/G；WILD的color必须为W。所有位置的cardId必须全局唯一；同一张牌不能同时出现在手牌和牌库等多个位置。注入时各玩家至少一张手牌。

fixture是缩小的规则场景，不要求凑齐60张，也不检查该局面是否可由一局真实随机游戏到达；允许不同cardId使用同一合法牌面。正常开局另行验证真实60张牌组成。样例与 fixture.schema.json 一起提供；JSON Schema表达结构，ID唯一性、跨字段关系还需业务校验。

成功动作revision恰好+1。被拒绝动作不改变完整状态。洗牌算法不限；回收时保留弃牌顶，其他弃牌进入牌库；不得复制或丢牌。最后一张功能牌仍先执行作用，再标记FINISHED；currentPlayerId保留该作用计算出的下一回合ID，即使游戏已结束。

## 错误状态

| 情况 | HTTP状态 |
|---|---|
| 非法fixture、缺少/错误万能颜色、未知动作、字段类型错误 | 400 |
| 玩家令牌无效 | 401 |
| 非成员、跨局访问、非房主开局、非当前玩家操作 | 403 |
| 资源不存在、测试模式关闭 | 404 |
| 不匹配或不持有的牌、版本过期、幂等冲突、终态操作、人数/准备/加入限制 | 409 |

并发动作失败方如果同时涉及回合及版本冲突，接受403或409。错误code建议使用INVALID_INPUT、INVALID_COLOR、UNAUTHENTICATED、FORBIDDEN、NOT_FOUND、INVALID_PLAY、INVALID_CARD、STALE_REVISION、IDEMPOTENCY_CONFLICT、GAME_ENDED等；当前检查HTTP状态和状态不变，不据文案打分。

## 最小调用顺序

创建fixture → 获取完整快照核对注入 → 用tokens.A调用普通GET → 用tokens.A提交动作 → 再取完整快照核对手牌、牌库、弃牌、回合、revision → 重放请求核对不再次变更。

这条链只证明所列接口场景的表现。仍需另行验证测试模式关闭、页面操作、同步、可维护性及更多随机组合，不能据此给出游戏“完成度100%”。
