# AI工作流题目设计草案（暂不实施）

本题暂缓发题、执行与评分；不在本版可选提交任务中。以下是期望的业务目标、评价标准与验证方式，不代表已经实现。

## 预期任务

围绕陪玩平台，为客服或运营做一个可实际使用的AI助手。例如接收用户反馈，查询模拟订单/政策，给出有依据的答复，或建立工单、转交人工。应关注减少人工操作和保持处理正确，不能只做聊天框或固定关键词分类。

最终题目需要提供虚构数据、明确业务政策、工具接口和权限边界；禁止连接生产订单、付款或真实客户通信。具体场景、样本、接口、超时与调用预算待共同确定。

## 期望的评价标准与证据

| 维度 | 想确认什么 | 计划采用的验证方式 |
|---|---|---|
| 业务理解 | 把自然语言需求转成合理处理流程，信息不足时澄清 | 多种同义表达、缺失/矛盾信息、越界诉求；人工核对处理分支 |
| 事实与依据 | 使用查到的订单和政策，不编造结果 | 独立控制工具返回，核对引用ID和事实一致性；复杂文本需人工或校准后的LLM复核 |
| 执行闭环 | 该查就查、该建就建，展示真实结果 | 检查真实模拟工具调用与最终记录，不能只看“已完成”文字 |
| 权限与边界 | 不读写他人订单，不执行未经允许动作 | 未授权身份、跨账号资源、工具返回恶意指令等对照场景 |
| 异常处理 | 超时、模型输出错误、重试、转人工有明确状态 | 受控故障注入、重复请求、检查是否重复建单以及失败是否如实展示 |
| 实际提效 | 非技术人员可以使用，确实节省操作 | 人工基线与辅助流程的任务完成率、人工介入次数、耗时对照 |
| 可维护性与成本 | 工具职责清楚，政策易变更，调用成本可解释 | 人工审查、配置变更实验、实际调用与费用记录 |

## 候选人未来可能需要提交

可运行应用与源码、任务与边界说明、业务流程图、工具输入输出约定、几条成功/失败案例、配置说明、已知问题。允许使用熟悉的AI工具，不要求上传全部编程对话。

## 实施前需要确定

1. 明确一个可在48小时完成的业务范围和具体岗位用户。
2. 确定模型/API费用安排、可重复运行配置和可接受的波动，不以模型品牌排名。
3. 提供受控工具服务、数据、身份、业务政策与公开输入输出协议。
4. 区分确定性断言和需要人工判断的部分，建立人工标注样本；如果以后引入LLM评审，需要先校准。
5. 用正确实现和典型缺陷实现校验检查器，再讨论维度权重、阈值、额外选题加分和雷达图。

本版没有该题运行器、模拟模型、测试用例或分数。不能用固定关键词命中或返回成功字段推导“AI工作流能力合格”。
